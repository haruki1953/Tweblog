我不打算用pocketbas的jssdk，我打算直接调用其REST-ish API
主要要针对的两个集合（数据库表）
images 集合
messages 集合
它们其中的字段
ImagesRecord = {
  alt?: string
  author: RecordIdString这个是当前登录用户的id后面会将
  created?: IsoDateString发送时不必设置
  id: string发送时不必设置

  imageBigHeight?: number
  imageBigWidth?: number
 
  imageSmall?: File
  imageSmallFileSize?: number
  imageSmallHeight?: number
  imageSmallWidth?: number
  
  imageTiny?: File
  imageTinyFileSize?: number
  imageTinyHeight?: number
  imageTinyWidth?: number
  
  isDeleted?: boolean发送时不必设置
  keyword?: string和本项目功能无关不必设置
  updated?: IsoDateString发送时不必设置

MessagesRecord = {
  author: RecordIdString这个是当前登录用户的id后面会将
  content?: string
  created?: IsoDateString发送时不必设置
  file?: RecordIdString和本项目功能无关不必设置
  id: string发送时不必设置
  images?: RecordIdString[]即图片id字符串数组，可以为0个，不能超过4个

  replyMessage?: RecordIdString回复的消息的id
  updated?: IsoDateString发送时不必设置
}

{

向messages集合发送请求返回如

需要提醒的一点是，MessagesRecord 不能同时有 content 和 images
准确的说是不能同时这样 content为非空字符串 images为长度大于0的数组
也就说消息不能同时为文字消息和图片消息，只能单独发送文字消息或图片消息
现在我来说一下我希望的，先发送文字消息，然后拿到文字消息的id，然后发送图片消息且replyMessage文字消息id

需要注意我希望的是，在发送消息前，将当前帖子的全部图片先处理并上传，这样就能拿到全部所需的图片id

和别的平台不一样的是，PocketChat不负责图片的处理
PocketChat再正常使用中，是由用户的前端来进行处理的
所以本项目tweblog要实现转发到PocketChat的功能，就也要自己来处理图片
本项目已安装了 "jimp": "0.22.12", 用jimp来进行图片处理

配置说明
bigConfig 大图的配置
imageConfig 中图的配置
smallConfig 小图的配置
tinyConfig 超小图的配置

format 为图片应处理为的格式
quality 为图片质量，为 0 到 1 之间的数字
sumWidthHeightLimit 为图片长宽之和的限制值，应按此值将图片处理为不同大小的图片，即图片长宽和如果超过此值，应将图片缩小为此值

如果图片长宽和小于imageConfig中的配置，那就不必上传大图imageBig，
imageBigWidth imageBigHeight 也为0即可

image imageSmall imageTiny 是必设置的
